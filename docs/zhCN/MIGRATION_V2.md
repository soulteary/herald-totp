# 升级至 v2.0.0

服务与 Go SDK 一起升级到主版本 v2，根模块改为
`github.com/soulteary/herald-totp/v2`，SDK 导入路径为
`github.com/soulteary/herald-totp/v2/pkg/heraldtotp`。HTTP 路由继续使用 `/v1`，
不要将模块主版本、HMAC 协议版本和 HTTP 路由版本混为一谈。

从 v1.2.8 升级时，HMAC 调用端和服务端必须共同迁移至绑定请求方法、路径、查询、
密钥 ID、时间戳、服务名、随机值和请求体摘要的 v2 协议。旧签名不再接受，也没有
回退开关。Redis 原子消费随机值，存储故障返回 503；无效或不完整的 HMAC 请求
不会回退至 API key。同时配置两种凭据的 SDK 只发送 HMAC。服务名为 1–128
字节，显式密钥 ID 最多 128 字节，按 UTF-8 字节而非字符计算。配置和 SDK
分别在启动、签名前检查，签名失败不得发送请求。

POST 请求必须使用 JSON。SDK 拒绝认证请求的重定向，应配置最终服务地址和经过
验证的 TLS。单个映射密钥仍允许省略 ID，多个映射密钥必须显式选择。只使用
API key 的部署仍受支持，可独立升级服务和调用端，但同样须满足 JSON 和重定向要求。

升级前保留 Redis 数据集和原加密密钥，暂停 HMAC 调用端并排空在途操作。部署
`ghcr.io/soulteary/herald-totp:v2.0.0`，升级包括 Herald 代理在内的所有调用端，运行
`go get github.com/soulteary/herald-totp/v2@v2.0.0` 并修改导入路径，使用 v2 SDK
或 `heraldtotp.SignRequest`。完成正确签名、重放拒绝和目标变更拒绝检查后恢复流量。
不要混用旧 HMAC 客户端和新服务。现有 TOTP 密钥、凭据和恢复码记录格式不变，
不要求用户重新绑定；更早版本的 enrollment 索引升级限制仍适用，见安全指南。

回滚必须协调服务和调用端版本，单独回滚一侧会导致认证失败，恢复 v1.2.8 也会恢复
旧协议的请求绑定及重放风险。整个过程保留 Redis 和加密密钥，失败响应不代表写入
未提交。发布流程仅接受与 `/v2` 模块匹配的正式 `v2.x.y` 标签，不发布 RC；部署请
固定完整版本，避免依赖会变动的主版本或 `latest` 标签。


## 从 v2.0.0 升级到 v2.0.1

v2.0.1 将注册确认纳入已有的 subject 每小时与对端 IP 每分钟配额。切换前检查
限额：开始、确认、验证和撤销共用计数，成功注册至少需要两次 subject 请求，
还应预留错误尝试和其他操作。subject 上限为一时，开始后确认必须等待小时
窗口重置，注册记录可能先过期。经共用 Herald 代理调用时，对端 IP 配额也
可能由多个调用方共享。

未知 enrollment ID 消耗 IP 预算；合法记录只使用存储的主体，不信任客户端
提供的 subject。每次确认只计一次 IP，并在解密和校验前检查配额。超限返回
`429/rate_limited`；Redis 配额故障拒绝请求，不消耗注册记录、不创建凭据。
成功响应、HMAC v2 和 Go `/v2` 导入路径保持不变。

升级和回滚保留 Redis、配额窗口、nonce/重放状态与原加密密钥，两个补丁版本
之间无需数据转换。不要清空计数或 pending 记录绕过 429。客户端应保留注册
上下文供重试，但仍须遵守原过期时间。旧代理可能把 429 映射为通用错误；
Herald v1.4.1 保留确认限流为 `429/rate_limited`。

回滚到 v2.0.0 会失去确认配额修复，虽能读取相同状态，却重新开放无配额确认
路径。回滚至 v2 之前的版本还会失去认证保护，必须遵循上文主版本限制，不要
因网关故障而单独降级该后端。

## 从 v2.0.1 升级到 v2.0.2

v2.0.2 的验证提交校验会比较当前启用凭据及其校验参数是否仍与验证
验证码时的快照一致。记录变化时拒绝提交，不推进该记录的计数，也不占用
challenge；同一凭据的并发计数推进仍受支持。不需要迁移凭据格式、存储键、
HTTP 成功响应或 SDK。

全部替换 TOTP 服务实例后才具备该校验；混合旧实例仍保留原提交行为，回滚也
会恢复它。保留现有 Redis 数据、加密密钥及重放状态。该校验不会撤销凭据
变化前已完成的提交。

替换服务实例时固定 `ghcr.io/soulteary/herald-totp:v2.0.2`。Go 调用端可运行
`go get github.com/soulteary/herald-totp/v2@v2.0.2`；SDK 线协议和 `/v1` HTTP
路径不变。JSON POST、HMAC v2 签名、nonce 有效期及共享配额规则继续适用，
不要求重新绑定 TOTP 或转换 Redis 数据。保留 pending 注册及其原过期时间、
配额窗口与重放记录。

滚动替换兼容现有存储，但只有新实例处理的验证请求具备快照校验。回滚到
v2.0.1 能读取相同状态，却会失去该校验；回滚不会撤销已完成的验证，也不会
恢复已消耗的验证码或 challenge。


## 从 v2.0.2 升级到 v2.0.3

部署 `ghcr.io/soulteary/herald-totp:v2.0.3`，Go 调用方可选择
`github.com/soulteary/herald-totp/v2@v2.0.3`。secure-kit v2.1.4 依赖修正诊断
字段中的 Unicode 脱敏；ASCII 输出和密码学操作不变。SDK 方法、HTTP 成功响应、
HMAC v2 签名及 nonce 身份、共享配额和凭据快照提交校验保持原有契约。

保留 Redis 数据、待确认注册、计数器和恢复码消费状态、nonce 与配额窗口、
命名空间及原加密密钥，无需转换数据或重新绑定。按正常方式替换服务实例；
仅更新 SDK 模块不会部署独立服务。服务回滚至 v2.0.2 会恢复旧 Unicode 脱敏行为，
同时保留该版本的快照校验和兼容状态。回滚不会撤销已完成操作，也不会改写应用
已经保存的诊断值。回滚到更早主版本仍须遵循上文的协同迁移要求。
